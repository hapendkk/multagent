# 13. Tools

Инструменты — то, чему я больше всего доверяю в этой системе. Не потому что они «правильные», а потому что в отличие от LLM они **считают, а не гадают**.: инструменты агентов и tool calling

## 13.1. Два класса инструментов

| Класс | Кто вызывает | Инструменты | Почему так |
|---|---|---|---|
| **Обязательные проверки (шлюз качества)** | Код валидатора, всегда | `check_contrast(html)` — все пары текст/фон страницы; `lint_html` — 9 правил; `render_screenshot` — Chromium в песочнице (Job Object) на 375/1280 px | Шлюз не должен зависеть от того, решит ли модель 3–4B вызвать инструмент. Пропуск проверки = пропущенный брак |
| **Вспомогательные (tool calling)** | Агент сам решает, через Ollama `tools` | `check_contrast(fg, bg, large_text)` — точный контраст пары и исправление; `read_skill(name)` — полный текст навыка по запросу | Агент проверяет свои решения до генерации и сам дочитывает нужные навыки |

Это осознанный гибрид. Тест T11 бенчмарка показал: ни одна из 7 моделей не посчитала контраст `#777` на белом правильно (верный ответ — 4.48:1). Поэтому:
- модель **не считает** контраст сама, а **вызывает инструмент**;
- финальную проверку всё равно делает код.

## 13.2. Где используется tool calling: подбор палитры

Перед генерацией HTML UI Generator выполняет шаг `plan_palette()`:

```
UI Generator ── chat_tools(model, tools=[check_contrast]) ──► Ollama
     ▲                                                                    │
     │       tool_calls: check_contrast(#ffffff, #3498db)                  │
     │◄───────────────────────────────────────────────────────────────────┘
     │ agent_tools.execute() → {"ratio": 3.15, "passes_aa": false, "suggestion": {...}}
     ├──────────────────────────────────────────────────────────────────► Ollama
     │       tool_calls: check_contrast(#ffffff, #1f5f5b) → 7.0, ok        │
     │◄───────────────────────────────────────────────────────────────────┘
     │ финальный ответ: JSON-палитра {bg, surface, text, muted, accent, accent_hover, on_accent}
     ▼
enforce_palette() — код перепроверяет 6 пар и исправляет оставшиеся провалы
     ▼
палитра передаётся в промпт генерации: «объяви эти токены в :root»
```

Цель — убрать главную причину провалов. В 3 из 4 FAIL-запусков ошибкой был контраст: кнопка 3.15:1, header 2.33:1, `button:hover` 1.7:1.

## 13.3. Агентный цикл (`llm.chat_tools`)

1. Запрос с `messages` и `tools`.
2. Если в ответе есть `tool_calls`, каждый вызов выполняется через `executor(name, args)`. Результат добавляется сообщением `{"role": "tool", "tool_name": ..., "content": JSON}`.
3. Цикл повторяется до текстового ответа или до `TOOL_MAX_ROUNDS = 4`. В последнем раунде инструменты не передаются, и модель обязана ответить.
4. Если модель не поддерживает tools (Ollama отвечает HTTP 400), выполняется обычный запрос без инструментов (`tools_supported = false`).

Траектория вызовов (раунд, инструмент, аргументы, результат) возвращается в `calls` и пишется в журнал запуска. Это источник данных для Observability (раздел 16).

## 13.4. Безопасность инструментов

| Мера | Реализация |
|---|---|
| Наименьшие привилегии | `AGENT_TOOLS`: allowlist на агента. Генератору (`ui_generator`) — только `check_contrast`; исследователю (`ux_researcher`) — только `read_skill`; остальным (Art Director, Validator) — ничего |
| Валидация аргументов | HEX по регулярному выражению; навык — только из доступных агенту |
| Инструмент не роняет граф | `execute()` никогда не бросает исключение, ошибка возвращается модели как `{"error": ...}`, и модель может исправиться |
| Нет побочных эффектов | Вспомогательные инструменты только читают и считают: нет сети, файловой записи и исполнения кода |
| Ограничение цикла | `TOOL_MAX_ROUNDS = 4` против зацикливания |
| Недоверенный код | Сгенерированный HTML исполняется только в песочнице Job Object (раздел 4) |
| Страховка результата | `enforce_palette()` перепроверяет палитру кодом, затем шлюз валидатора проверяет всю страницу |

## 13.5. Проверка

`tests/test_tool_calling.py` (7 тестов без Ollama):
- точность `check_contrast` на T11;
- allowlist и валидация;
- агентный цикл с подменённым Ollama: вызов → результат → финальный ответ;
- лимит раундов;
- fallback для моделей без tools;
- `enforce_palette` исправляет `#3498db`/`#5dade2`/`#aaaaaa`;
- работа при недоступной Ollama.

Всего в проекте 23 теста. Поддержка tools проверена по документации Ollama для qwen3.5 и llama3.2. Реальный прогон с моделями нужно выполнить на ноутбуке: на VM нет GPU и Ollama.
