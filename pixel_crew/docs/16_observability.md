# 16. Observability

## 16.0. Термины (для защиты)

- **Лог** — отдельное событие с меткой времени: «run.start», «llm.error», «tool.error». Отвечает на вопрос «что произошло и когда».
- **Спан** — минимальная единица работы с длительностью: один вызов LLM, один инструмент, один агент, один рендер. Имеет `span_id`, `parent_id`, `attributes`.
- **Трейс** — дерево спанов одного запуска, связанных общим `trace_id`. Отвечает на вопрос «как шёл запрос от начала до конца и где потеряли время».
- **Траектория агентов** — то же дерево, но в терминах системы: агент → его вызовы LLM/инструментов/песочницы в порядке выполнения (`trajectory.json` на запуск).
- **Метрика** — агрегат по запуску или по истории: исход, попытки, время, токены, ошибки, ток/с по моделям (`metrics.jsonl`).
- **Алерт** — сработавшее правило из `config.ALERTS` (`alerts.jsonl` + консоль).

## 16.1. Что собирается

| Сигнал | Где | Содержимое |
|---|---|---|
| **Трейсы** | `outputs/telemetry/traces.jsonl` | Спан на каждый шаг: агент (`agent.*`), вызов LLM (`llm.chat`), инструмент (`tool.*`), рендер в песочнице (`sandbox.render`). Поля как в OpenTelemetry: `trace_id`, `span_id`, `parent_id`, `duration_ms`, `status`, `attributes` |
| **Логи** | `logs.jsonl` | Структурные события (`run.start`, `run.finish`, `llm.error`, `tool.error`) с `trace_id` и `span_id` для связи с трейсом. Плюс человекочитаемый журнал в консоли и `report.json` |
| **Метрики** | `metrics.jsonl` (запись на запуск) | исход, попытки, время запуска и каждого агента, число вызовов LLM и ошибок, токены вход/выход и ток/с по моделям, вызовы инструментов, время рендера, доступность песочницы |
| **Алерты** | `alerts.jsonl` и консоль | правила из `config.ALERTS`, см. 16.3 |
| **Траектория агентов** | `outputs/run_*/trajectory.json` | Дерево: агент → его вызовы LLM, инструментов, песочницы, в порядке выполнения, с атрибутами (модель, токены, качество, провалы контраста) |

Атрибуты спанов агентов: `attempt`, `generator_model`, `outcome`. Для валидатора добавляются `quality`, `contrast_failures`, `lint_errors`. Для LLM — `model`, `tokens_in`, `tokens_out`, `tool_calls`, `schema`. Для инструментов — аргументы и ошибка.

## 16.2. Инструментирование

Код агентов почти не менялся. Телеметрия встроена в 4 точки:
- `graph.py`: каждый узел обёрнут `traced_node()`;
- `llm._call`: все запросы к Ollama, обычные и tool calling;
- `agent_tools.execute`: инструменты, которые вызывает агент;
- `tools.render_screenshot`: песочница (Job Object).

Трейс начинается в `main.py` (`thread_id` = `trace` = `run_…`) и завершается `obs.finish()`. Эта функция считает метрики, проверяет алерты и строит траекторию.

## 16.3. Алерты

| Правило | Уровень | Условие | Что значит |
|---|---|---|---|
| `slow_run` | warning | запуск > 420 с | нарушение SLO по латентности |
| `llm_errors` | critical | есть ошибки Ollama | модель не загружена или таймаут |
| `sandbox_down` | critical | рендер недоступен | Job Object недоступен, проверки рендера не выполнены (fail-closed) |
| `slow_model` | warning | < 8 ток/с при > 50 токенах | модель вытеснена из 6 ГБ VRAM в RAM |
| `needs_human` | warning | низкая уверенность валидатора | нужен человек |
| `run_failed` | warning | FAIL после всех попыток | брак |
| `pass_rate_drop` | critical | pass rate < 50 % за последние 10 запусков (минимум 5) | регресс качества после правки промптов или моделей |

## 16.4. Просмотр

```bat
python observability.py           :: сводка: исходы, p50/p95, токены, ток/с по моделям, последние алерты
set PIXEL_TELEMETRY=0             :: отключить запись телеметрии
```

## 16.5. Почему stdlib, а не Langfuse/Phoenix сразу

Сначала я хотела поставить Langfuse — все его хвалят. Но когда дошло до установки, выяснилось: Postgres + ClickHouse + Docker, а у меня ноутбук, где уже живут Ollama и 6 ГБ VRAM. Перегнуло. Поэтому написал свой стек на stdlib:

- Локальность (N1) и ноль инфраструктуры. Langfuse требует Postgres и ClickHouse (в Docker), что тяжело для ноутбука с 16 ГБ, где уже работает Ollama.
- Формат спанов совпадает с полями OpenTelemetry. Переход на Arize Phoenix (`pip install arize-phoenix`, OTLP) или Langfuse — это замена `_write` на экспортёр OTLP, без правок агентов.
- Метрики для Evals (раздел 15) и телеметрия — одни и те же числа, а не две параллельные системы.
