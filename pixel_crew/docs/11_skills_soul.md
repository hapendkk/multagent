# 11–12. Системные промпты, skills и семантические .md (SOUL)

## 11.1. Из чего собирается системный промпт

Первый промпт у меня получился монолитным — один файл на 300 строк, и модель на нём тонула. Разделила на слои: общие ценности студии, характер каждого агента, роль и подключаемые навыки. Собирается так (`skills.build_system()`):

```
crew/SOUL.md              общие миссия, ценности, вкус, красные линии студии
crew/souls/<агент>.md     характер, приоритеты, привычки, анти-паттерны агента
crew/USER.md, AGENTS.md   (Art Director) для кого работаем, состав команды и передачи
crew/TOOLS.md             (Validator) что измеряют инструменты и как их трактовать
prompts/<агент>.md        роль: задача, формат ответа, жёсткие требования, границы
skills/*/SKILL.md         0–3 навыка, выбранных под задачу
```

Почему так, а не один большой промпт:
- **Разделение «кто ты» и «что делаешь».** SOUL и души задают устойчивые ценности и характер (по аналогии с `SOUL.md` в OpenClaw). Промпт роли задаёт конкретную задачу. Их можно менять независимо.
- **Общие ценности в одном месте.** «Доступность важнее эффектности» и «не выдумывать факты» написаны один раз и попадают всем агентам.
- **Маленький контекст 3–4B моделей.** Каждый агент получает только нужные общие файлы и не больше 3 навыков (`SKILLS_MAX`, `SKILLS_BUDGET_CHARS = 3200`). Итоговый промпт — 3–5.5 тыс. символов (~1–1.5 тыс. токенов).

## 11.2. Семантические .md

| Файл | Смысл | Кто получает |
|---|---|---|
| `crew/SOUL.md` | Миссия, 5 ценностей по приоритету, вкус, красные линии | все |
| `crew/souls/art_director.md` | Спокойный, коротко; название из одного алфавита | Art Director |
| `crew/souls/ux_researcher.md` | Эмпатичный, гипотезы называет гипотезами | UX Researcher |
| `crew/souls/ui_generator.md` | Аккуратный ремесленник; токены, сетка; на доработке меняет только нужное | UI Generator |
| `crew/souls/validator.md` | Строгий, но справедливый; числа инструментов важнее мнения | Validator |
| `crew/AGENTS.md` | Таблица ролей: делает / не делает / кому передаёт | Art Director |
| `crew/USER.md` | Для кого работаем, что ценят и чего не любят | Art Director |
| `crew/TOOLS.md` | Что измеряет каждый инструмент и как трактовать результат | Validator |

## 11.3. Skills

Формат — как у Agent Skills (Anthropic): папка с `SKILL.md` и YAML-шапкой. Шапка нужна для выбора, тело — инструкция.

```yaml
---
name: mobile-first-layout
description: Раскладка mobile-first без горизонтального скролла на 375 px
agents: [ui_generator]          # кому доступен
product_types: [any]            # или [dashboard], [form], [landing_page]
always: true                    # базовый навык роли
triggers: [горизонтальн, скролл, overflow]   # слова из замечаний валидатора
---
```

| Навык | Агенты | Когда подключается |
|---|---|---|
| `brief-to-task` | Art Director | всегда: название из одного алфавита, шкала сложности |
| `ux-persona-scenario` | UX Researcher | всегда: JTBD, сценарий, зона большого пальца |
| `mobile-first-layout` | UI Generator | всегда; первым при замечании о скролле |
| `wcag-safe-palette` | UI Generator | всегда; первым при замечании о контрасте (hover темнее базы) |
| `apply-review-feedback` | UI Generator | на доработке |
| `dashboard-layout` | UI Generator, UX | тип `dashboard` |
| `form-design` | UI Generator, UX | тип `form` |
| `landing-hero` | UI Generator, UX | тип `landing_page` |
| `design-review-rubric` | Validator | всегда: рубрика качества 0–100 |

**Алгоритм выбора** (`skills.select_skills`):
- +3 балла, если совпал тип экрана;
- +4, если слово-триггер есть в замечаниях валидатора;
- +1, если навык базовый (`always`).

Навыки сортируются по баллам и берутся, пока не превышены 3 штуки и 3200 символов. Это *progressive disclosure*: модель видит только то, что нужно в этой задаче.

**Связь с найденными проблемами.**
- Частые провалы контраста на hover → `wcag-safe-palette`.
- Переполнение 395 px на телефоне → `mobile-first-layout`.
- Название «Сereni» из двух алфавитов → `brief-to-task`.

Список выбранных навыков пишется в журнал запуска (`skills: …`) и попадает в `report.json`.

## 11.4. Проверка

`tests/test_skills.py`:
- корректность шапок всех навыков;
- выбор по типу экрана;
- приоритет навыка по замечанию;
- лимиты и границы по агентам;
- в промпте валидатора есть SOUL, душа, TOOLS, роль и рубрика.

Связанная правка: голоса Jev-like теперь идут с `num_ctx = 8192` (`DECISION_NUM_CTX`). Иначе у Ollama окно контекста по умолчанию могло обрезать промпт валидатора вместе с кодом страницы.
